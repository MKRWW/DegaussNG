# Spec 0004: M3 Fake BIOS boot screen

Status: Reviewed. Closes issue #5.

## Goal

When the app starts with Windows, a fake BIOS boot screen runs for six seconds: a power-on beep, a
processor gag, a counting memory test and a seeking floppy drive. Any key or click ends it at once.
The screen can also be started from the tray.

## Public signatures (DegaussNG.Core)

```csharp
// Added to AppConfig, and copied by Normalized()
public bool BootEnabled { get; init; } = true;

public sealed record BootInfo(long MemoryKilobytes, int Cores, int Megahertz);

public static class BootScript
{
    public const double TotalSeconds = 6.0;
    public const double MemoryStartSeconds = 1.2;
    public const double MemoryEndSeconds = 3.0;
    public const double FloppyStartSeconds = 3.2;
    public const double FloppyEndSeconds = 5.0;
    public const string Footer = "Press DEL to enter SETUP";

    public static long MemoryCounterAt(long memoryKilobytes, double seconds, bool reducedMotion);
    public static IReadOnlyList<string> LinesAt(BootInfo info, double seconds, bool reducedMotion);
}

public static class AutostartCommand
{
    public const string Argument = "--autostart";
    public static string Build(string executablePath);          // "\"<path>\" --autostart"
    public static bool IsOurs(string? value, string executablePath); // value equals Build(path), ignoring case
}
```

## Behaviour

### BootScript

`MemoryCounterAt`:

- Before `MemoryStartSeconds` it returns 0.
- From `MemoryEndSeconds` on it returns `memoryKilobytes` exactly.
- In between it returns `memoryKilobytes * p` with `p = (seconds - MemoryStartSeconds) / (MemoryEndSeconds - MemoryStartSeconds)`,
  rounded down to a multiple of 1024. It never decreases.
- With `reducedMotion` it returns `memoryKilobytes` from `MemoryStartSeconds` on, so nothing counts.

`LinesAt` returns the screen rows that are visible at `seconds`, in this order. A row appears once
`seconds` reaches its time. Numbers use the invariant culture without thousands separators.

| From | Row |
|---|---|
| 0.20 | `DegaussNG Retro BIOS v1.0, a very green product` |
| 0.20 | `Copyright (C) 1994-2026 DegaussNG contributors` |
| 0.20 | empty row |
| 0.60 | `Main Processor : 486DX2-66 compatible` |
| 1.00 | `                 ...correction: {Cores} cores at {Megahertz} MHz. Turbo ON.` When `Megahertz` is 0: `                 ...correction: {Cores} cores. Turbo ON.` |
| 1.20 | `Memory Testing : {MemoryCounterAt}K`, plus ` OK` from `MemoryEndSeconds` on |
| 3.20 | `Detecting Floppy Drive A: ...`, plus ` 1.44M 3.5 in. OK` from `FloppyEndSeconds` on |
| 5.30 | empty row |
| 5.30 | `Starting operating system...` |

The footer is not part of `LinesAt`. No row names a real manufacturer, product or trademark.

### AutostartCommand

`Build` puts the path in double quotes and appends a space and `--autostart`. `IsOurs` is false for
null and for an empty value.

### SystemInfo (app)

`internal static BootInfo Read()`:

- `MemoryKilobytes` is `GC.GetGCMemoryInfo().TotalAvailableMemoryBytes / 1024`.
- `Cores` is `Environment.ProcessorCount`.
- `Megahertz` is the DWORD `~MHz` under `HKEY_LOCAL_MACHINE\HARDWARE\DESCRIPTION\System\CentralProcessor\0`.
  Every failure gives 0 and is logged. No P/Invoke.

### Autostart (app)

`internal static class Autostart` with `bool IsEnabled()`, `void Enable()` and `void Disable()`. It works
on the value `DegaussNG` under `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`, with
`Environment.ProcessPath` as the executable path.

- `IsEnabled` is `AutostartCommand.IsOurs(value, path)`.
- `Enable` writes `AutostartCommand.Build(path)`. `Disable` deletes the value and does nothing when it is missing.
- Exceptions are logged. `IsEnabled` then returns false.
- Nothing is written to the registry unless the user switches the tray item on.

### SoundPlayer

- `PlayBoot(double volume)` plays the embedded resource `DegaussNG.assets.sounds.boot.wav`. While a boot
  sound plays, a further call does nothing.
- `StopBoot()` stops it. Without one it does nothing. Disposal uses the existing `PlaybackStopped` path,
  the same way as the modem sound.

### BootWindow and BootRunner (app)

`internal sealed class BootRunner` with `Task<BootResult> RunAsync()` and `void Close()`, where
`internal sealed record BootResult(int Monitors, string ClosedBy, double Seconds)`. It takes the
existing `RunGate`, the `AppConfig` and the `SoundPlayer` (null for no sound) in its constructor, plus
`UpdateConfig(AppConfig)`.

- When the gate is busy, `RunAsync` returns `BootResult(0, "busy", 0)` at once. Degauss and boot screen
  therefore never overlap.
- One `BootWindow` per monitor from `System.Windows.Forms.Screen.AllScreens`. Each window is borderless,
  topmost, black, not in the taskbar, and placed with `SetWindowPos` on the physical bounds of its
  monitor, again after `ContentRendered`, like `OverlayWindow`. It is not click-through and it may activate.
- Only the window on the primary monitor shows text: a `Consolas` `TextBlock` in `#AAAAAA` with a margin of
  2 percent of the window height, the rows of `LinesAt` and a cursor `_` after the last row, and the
  footer at the bottom left. The font size is the window height divided by 30, in device independent
  units. The cursor blinks at 2 Hz, and stays on with reduced motion.
- `BootInfo` is read once per run with `SystemInfo.Read()`.
- A `DispatcherTimer` with 30 ms refreshes the text from a `Stopwatch` that starts together with
  `PlayBoot`. After the first window is shown, the primary window calls `Activate()`.
- Closing reasons: `end` when `TotalSeconds` is reached, `key` on `KeyDown` in any boot window, `mouse` on
  `MouseDown` in any boot window, `close` through `Close()`, `watchdog` after 10 seconds.
- Every close path stops the boot sound, stops the timer, closes all windows and leaves the gate. The
  result holds the monitor count, the reason and the elapsed seconds.

### Tray

New menu order: `Degauss now`, `Modem test`, `Boot screen now`, separator, `Degauss enabled`,
`Reduced motion`, `Modem sound`, `Modem mode`, `Boot screen at startup` (check, `BootEnabled`),
`Start with Windows` (check), `Volume`, `Change hotkey...`, separator, `Exit`.

- `Boot screen now` always runs the boot screen, also when `Boot screen at startup` is off.
- `Start with Windows` shows `Autostart.IsEnabled()` when the menu opens, and calls `Enable` or `Disable` on click.
- `TrayController` gets `void RunBootScreen()`, which runs the boot screen when `BootEnabled` is true.
- `Dispose` closes a running boot screen. It stays safe to call twice.

### App

- With the argument `--autostart`, the app starts as usual and then calls `RunBootScreen()` once.
  Without it no boot screen runs at start. The single-instance mutex applies as before.
- `DegaussNG.exe --boot <logPath>` runs without tray, hotkey or config access and ignores the mutex. It
  runs the boot screen once with sound at volume 0.5 and reduced motion off, writes
  `monitors=<n> closedBy=<reason> seconds=<s.ss>` with invariant culture, and exits with 0 when at least
  one window was shown, otherwise with 1. Any key ends it early as usual.

### Sound (`tools/SoundSynth`)

`Program` also writes `boot.wav`. `BootSound` exposes:

```csharp
public static class BootSound
{
    public const int SampleRate = 22050;
    public const double DurationSeconds = 5.2;
    public const int TotalSamples = 114660;
    public static short[] Render();
}
```

Times are seconds from the start of the file.

| From | To | Content |
|---|---|---|
| 0.00 | 0.20 | Digital silence |
| 0.20 | 0.35 | Power-on beep: square wave `sign(sin(2 pi 1000 t))`, gain 0.5, through a one-pole low-pass with coefficient 0.3 |
| 3.20 | 5.00 | Motor: white noise through a band-pass at 120 Hz with Q 2, gain 0.25, 50 ms linear fades at both edges |
| 3.30 | 4.45 | Head seek: 5 passes, pass k starts at `3.30 + 0.253 k`, 16 steps per pass, one step every 1/120 s |
| 4.90 | 5.00 | Clunk: `0.8 sin(2 pi 180 t) exp(-t / 0.03)` plus noise times `exp(-t / 0.004)` |
| 5.00 | 5.20 | Digital silence apart from filter tails |

- One step at local time `t`: noise times `0.6 exp(-t / 0.002)` plus `0.5 sin(2 pi f t) exp(-t / 0.01)`,
  each step 15 ms long. In a pass `f` starts at 700 Hz and rises 20 Hz per step. Odd passes run the
  same frequencies downwards.
- Afterwards the whole signal passes `tanh(1.2 x)`. Peak-normalize to -6 dBFS. A linear fade over the
  last 20 ms makes the last sample exactly 0. The first 0.20 s stay exactly 0.
- All randomness uses an own xorshift32 generator with a fixed seed. `System.Random` is not used.

## Acceptance criteria

- AC1: Given a clean checkout, `dotnet build -c Release` succeeds with 0 warnings.
- AC2: A config without `BootEnabled` loads it as true, and false survives a save and load and `Normalized()`.
- AC3: `MemoryCounterAt(16777216, t, false)` is 0 before 1.2, 16777216 from 3.0 on, a multiple of 1024 in
  between, and never decreases for t from 0 to 6 in 10 ms steps.
- AC4: With reduced motion `MemoryCounterAt` is 0 before 1.2 and the full value from 1.2 on.
- AC5: `LinesAt` at 0.1 is empty, at 0.7 has 4 rows ending with the processor row, at 2.0 contains a
  memory row without ` OK`, and at 5.5 has 9 rows ending with `Starting operating system...`, with the
  memory row `Memory Testing : 16777216K OK` and the floppy row ending with ` 1.44M 3.5 in. OK`.
- AC6: The correction row reads `...correction: 16 cores at 3200 MHz. Turbo ON.` for 16 and 3200, and
  `...correction: 4 cores. Turbo ON.` for 4 and 0.
- AC7: No row of `LinesAt` at 6.0 and not the footer contains, ignoring case, `intel`, `amd`, `award`,
  `phoenix`, `american megatrends`, `microsoft` or `windows`.
- AC8: `AutostartCommand.Build(@"C:\Apps\DegaussNG.exe")` is `"C:\Apps\DegaussNG.exe" --autostart`.
  `IsOurs` accepts it in other letter case, and rejects null, an empty value, another path and the path
  without the argument.
- AC9: `BootSound.Render()` has exactly 114660 samples, is identical across two calls and matches the
  committed `boot.wav`, which is PCM mono at 22050 Hz.
- AC10: The first 0.20 s are exactly 0, the peak is at most -6 dBFS and the last sample is 0.
- AC11: In 0.20 to 0.35 the power at 1000 Hz is at least 10 times the power at 1500 Hz.
- AC12: From 0.50 to 3.15 every sample is at most 2 in magnitude.
- AC13: The RMS from 3.30 to 4.45 is at least twice the RMS from 4.50 to 4.85.
- AC14 (gate, measured): `DegaussNG.exe --boot <log>` exits with 0 and writes `closedBy=end` with seconds
  between 5.9 and 6.6. A key press during the run gives `closedBy=key`.
- AC15 (manual): The tray item `Boot screen now` shows the screen with beep and floppy, a key ends it, and
  `Start with Windows` plus a new sign-in shows it after login.

## Do NOT

- No change to the degauss or modem sounds, their WAV files or their behaviour.
- No third-party samples, fonts or NuGet packages. No real manufacturer names or logos.
- No P/Invoke additions. No files outside the Files section.
- No mention of tools, assistants or automation in code comments or documents.
- Do not write the registry anywhere except in `Autostart.Enable` and `Autostart.Disable`, and do not call
  them from tests.
- Do not use web search. Do not run git commands.
