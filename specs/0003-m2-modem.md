# Spec 0003: M2 Modem dial-up sound

Status: Reviewed. Closes issue #3.

## Goal

When the network really becomes connected, the app plays a synthesized dial-up modem sound once.
Short mode is the default, full mode is for purists. A click on the tray icon stops it.

## Public signatures (DegaussNG.Core)

```csharp
public static class ModemModes
{
    public const string Short = "Short";
    public const string Full = "Full";
}

// Added to AppConfig
public bool ModemEnabled { get; init; } = true;
public string ModemMode { get; init; } = ModemModes.Short;

public sealed class ConnectionDebouncer
{
    public static readonly TimeSpan DefaultStableOnline = TimeSpan.FromSeconds(4);
    public static readonly TimeSpan DefaultMinimumOffline = TimeSpan.FromSeconds(8);
    public static readonly TimeSpan DefaultCooldown = TimeSpan.FromSeconds(60);

    public ConnectionDebouncer(bool initiallyConnected);
    public ConnectionDebouncer(bool initiallyConnected, TimeSpan stableOnline, TimeSpan minimumOffline, TimeSpan cooldown);
    public void Report(bool connected, TimeSpan now);
    public bool Poll(TimeSpan now); // true exactly once per real connection
}

public static class AdapterRules
{
    public static bool IsRealAdapter(NetworkInterfaceType type, string name, string description);
}
```

`AppConfig.Normalized()` keeps `ModemEnabled` and maps `ModemMode` to `Full` when it equals `Full`
ignoring case, and to `Short` for every other value.

## Behaviour

### ConnectionDebouncer

The debouncer holds a confirmed state, which starts as `initiallyConnected`, the last reported state
and the time of the last reported change.

- `Report` updates the last reported state and the change time only when the state differs.
- `Poll` while the last report is offline: when the state is confirmed online and the offline time has
  reached `minimumOffline`, the confirmed state becomes offline. Returns false.
- `Poll` while the last report is online: when the state is confirmed offline and the online time has
  reached `stableOnline`, the confirmed state becomes online. It returns true unless the previous
  firing is less than `cooldown` ago.
- In every other case `Poll` returns false.

So an app start on a connected network stays silent, a short drop or roaming between access points
stays silent, and flicker while connecting produces one single firing.

### AdapterRules

`IsRealAdapter` is true only for the types `Ethernet`, `GigabitEthernet`, `FastEthernetT`,
`FastEthernetFx`, `Wireless80211`, `Wwanpp` and `Wwanpp2`, and only when neither name nor description
contains, ignoring case, one of: `virtual`, `vethernet`, `hyper-v`, `vmware`, `virtualbox`, `wsl`,
`docker`, `tap-`, `tap adapter`, `tunnel`, `vpn`, `wireguard`, `tailscale`, `zerotier`, `loopback`,
`bluetooth`, `npcap`, `pseudo`.

### NetworkWatcher

`internal sealed class NetworkWatcher : IDisposable` with `event Action? Connected`, `void Start()` and
`static bool IsConnected()`.

- `IsConnected()` is true when an adapter with `OperationalStatus.Up` passes `AdapterRules` and has a
  default gateway other than `0.0.0.0` and `::`. Exceptions are logged and count as not connected.
- `Start` creates the debouncer from `IsConnected()`, subscribes to
  `NetworkChange.NetworkAddressChanged` and `NetworkChange.NetworkAvailabilityChanged`, and starts a
  `DispatcherTimer` with a 1 second interval. A `Stopwatch` provides the time.
- The network events arrive on other threads, so they use `Dispatcher.BeginInvoke` to report the state.
- Every timer tick calls `Poll`. Every fifth tick also reports `IsConnected()`. `Connected` is raised
  when `Poll` returns true.
- `Dispose` unsubscribes the events and stops the timer.

### SoundPlayer

- `PlayModem(string mode, double volume)` plays `modem-full.wav` for `Full`, otherwise
  `modem-short.wav`, from the embedded resources `DegaussNG.assets.sounds.modem-short.wav` and
  `DegaussNG.assets.sounds.modem-full.wav`. While a modem sound plays, a further call does nothing.
- `StopModem()` stops the running modem sound. Without one it does nothing.
- Stopped sessions are disposed through the existing `PlaybackStopped` path.
- The existing `Play(double volume)` for the degauss sound keeps working and can overlap the modem.

### Tray

New menu order: `Degauss now`, `Modem test`, separator, `Degauss enabled`, `Reduced motion`,
`Modem sound` (check), `Modem mode` (submenu `Short` and `Full`, radio style), `Volume`,
`Change hotkey...`, separator, `Exit`.

- `NetworkWatcher.Connected` plays the modem sound when `ModemEnabled` is true.
- `Modem test` always plays the selected mode, also when `Modem sound` is off.
- `NotifyIcon.MouseDown`, `NotifyIcon.Click` and `ContextMenuStrip.Opening` call `StopModem()`.
- `Dispose` stops the modem sound and disposes the watcher. It stays safe to call twice.

### Network state report

`DegaussNG.exe --netstate <logPath>` runs without tray, hotkey, sound or config access and ignores the
single-instance mutex. It writes the first line `connected=<true|false>`, then one line per adapter
`<name>|<type>|<status>|real=<true|false>|gateway=<true|false>`, and exits with code 0.

### Sound (`tools/SoundSynth`)

`Program` also writes `modem-short.wav` and `modem-full.wav`. `ModemSound` exposes:

```csharp
public sealed record ModemSection(string Name, double StartSeconds, double DurationSeconds);

public static class ModemSound
{
    public const int SampleRate = 22050;
    public static IReadOnlyList<ModemSection> ShortSections { get; }
    public static IReadOnlyList<ModemSection> FullSections { get; }
    public static short[] RenderShort();
    public static short[] RenderFull();
}
```

Sections run in the listed order without gaps. Durations are in seconds.

| Name | Short | Full | Content |
|---|---|---|---|
| `silence` | 0.20 | 0.20 | Digital silence |
| `offhook` | 0.05 | 0.10 | Click |
| `dialtone` | 0.40 | 2.00 | 350 Hz + 440 Hz, gain 0.45 each |
| `dtmf` | 0.70 | 1.40 | Digits 5550199. Short: 0.07 on, 0.03 off. Full: 0.12 on, 0.08 off. Gain 0.4 per tone |
| `line` | 0.10 | 1.00 | Noise at gain 0.01 |
| `ringback` | none | 1.50 | 440 Hz + 480 Hz, gain 0.35 each |
| `pickup` | none | 0.50 | Noise at gain 0.01 |
| `answer` | 0.80 | 3.30 | 2100 Hz, phase reversal every 0.45 s, 15 Hz amplitude modulation of depth 0.2, gain 0.7 |
| `fsk` | 0.50 | 1.80 | 300 baud random bits. First half 1080 Hz plus or minus 100 Hz, second half 1750 Hz plus or minus 100 Hz, phase-continuous, gain 0.55 |
| `probe` | 0.25 | 1.00 | Sum of tones from 150 Hz to 3750 Hz in 150 Hz steps with fixed random phases, peak-normalized, gain 0.5 |
| `bong` | 0.60 | 1.50 | 1200 Hz and 2400 Hz alternating every 0.15 s, starting with 1200 Hz, gain 0.6 |
| `sweep` | 0.40 | 1.60 | Linear chirps from 600 Hz to 3000 Hz of 0.4 s each, phase-continuous, gain 0.55 |
| `training` | 0.60 | 6.00 | 1829 Hz carrier with a random phase out of 45, 135, 225, 315 degrees at 3200 symbols per second. I and Q pass a one-pole low-pass with coefficient 0.5. Gain 0.6 |
| `data` | 0.50 | 3.00 | White noise through a band-pass at 2000 Hz with Q 0.6, times `1 + 0.15 sin(2 pi 7 t)`, gain 0.6 |
| `connect` | 0.05 | 0.10 | Click |
| `end` | 0.10 | 0.20 | Digital silence |

- Click: noise times `exp(-t / 0.006)`, gain 0.8.
- Every section except `silence`, `offhook`, `connect` and `end` has a 3 ms linear fade at both edges.
- Each section length in samples is `round(duration * 22050)`. `StartSeconds` is the sample position
  divided by the sample rate.
- Afterwards the whole signal passes the telephone line: a 300 Hz high-pass and a 3400 Hz low-pass,
  both RBJ biquads with Q 0.707, then `tanh(1.2 x)`.
- Peak-normalize to -6 dBFS. A linear fade over the last 20 ms makes the last sample exactly 0. The
  first 0.20 s stay exactly 0.
- All randomness uses an own xorshift32 generator with a fixed seed. `System.Random` is not used.

## Acceptance criteria

- AC1: Given a clean checkout, `dotnet build -c Release` succeeds with 0 warnings.
- AC2: A config without modem fields loads with `ModemEnabled` true and `ModemMode` `Short`.
  `"full"` loads as `Full`, `"nonsense"` as `Short`, and `ModemEnabled` false survives a save and load.
- AC3: An instance created as connected never fires on repeated polls.
- AC4: Offline at creation, connected at t=10, polled every second: fires exactly once at t=14.
- AC5: Connected, offline at t=10, online again at t=15, polled every second to t=120: never fires.
- AC6: Connected, offline at t=10, online at t=30: fires exactly once at t=34.
- AC7: Offline, then online, offline, online with 1 second spacing, then stable: fires exactly once,
  4 seconds after the last change.
- AC8: A second real connection within 60 seconds after a firing stays silent. A later one fires.
- AC9: `AdapterRules` accepts `Wi-Fi` as `Wireless80211` and `Ethernet` as `Ethernet`. It rejects
  `vEthernet (WSL)`, `Tailscale`, `Hyper-V Virtual Ethernet Adapter`, `Bluetooth Network Connection`,
  and the type `Loopback`.
- AC10: `RenderShort` lasts 5.0 to 5.5 seconds and `RenderFull` 24.5 to 26.0 seconds. Both renders are
  identical across two calls and match the committed WAV files, which are PCM mono at 22050 Hz.
- AC11: In both modes the first 0.20 s are exactly 0, the peak is at most -6 dBFS and the last sample is 0.
- AC12: In `dialtone`, the Goertzel power at 350 Hz and at 440 Hz is each at least 5 times the power at 1000 Hz.
- AC13: In both modes all seven digits of `dtmf` decode to 5550199 from the strongest low tone out of
  697, 770, 852, 941 Hz and the strongest high tone out of 1209, 1336, 1477 Hz.
- AC14: In `answer`, the power at 2100 Hz is at least 20 times the power at 1000 Hz and at 3000 Hz. In
  full mode the phase at 2100 Hz differs by pi plus or minus 0.5 radians between the 50 ms before and
  the 50 ms after the first reversal.
- AC15: In `bong`, 1200 Hz is stronger than 2400 Hz in the first 0.15 s, and weaker in the next 0.15 s.
- AC16: In `training` of full mode, no single frequency from 300 to 3400 Hz in 50 Hz steps holds more
  than 20 percent of the summed power of those frequencies, and the power at 5000 Hz is below one
  tenth of their average.
- AC17 (manual): Switching Wi-Fi off and on again plays the sound once, a tray click stops it, and
  starting the app on a connected network stays silent.
